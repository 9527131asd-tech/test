# 校园活动推荐与地理围栏签到系统设计方案

## 1. 项目目标

为学生和校园活动组织者提供一个微信小程序。学生可浏览、筛选、报名活动，并在活动现场完成定位签到；组织者可发布活动、管理报名名单和查看签到记录。

本项目面向本科毕业设计，推荐功能采用可解释的规则排序，不训练机器学习模型。定位签到采用用户授权的位置与活动设置地点计算距离，并记录本次判断结果。定位本身可能受设备精度或模拟位置影响，因此系统将其作为签到辅助核验，不宣称具备强防作弊能力。

## 2. 建议技术栈

- 学生端：微信原生小程序（WXML、WXSS、JavaScript）。
- 后端：Java 17、Spring Boot、Spring Web、Spring Validation、MyBatis。
- 数据库：MySQL 8。
- 接口格式：REST API，JSON 请求与响应。
- 开发调试：微信开发者工具、IntelliJ IDEA、MySQL Workbench 或 Navicat。
- 管理端：第一版可使用简单的管理页面；如果时间有限，可先用后端管理接口配合数据库工具完成管理，不必另做复杂前端。

不要把 AppSecret、数据库密码或真实用户信息提交到 GitHub；本地配置使用环境变量或未提交的配置文件。

## 3. 用户与功能范围

### 学生

1. 查看活动列表，按类别、日期和状态筛选。
2. 查看活动详情、时间、地点、剩余名额和签到范围。
3. 报名或取消报名。
4. 查看按个人兴趣和活动条件排序的推荐列表。
5. 在活动有效时间内授权定位并签到。
6. 查看自己的报名与签到记录。

### 活动组织者或管理员

1. 新建、修改、发布、下架活动。
2. 设置活动地点坐标、允许签到半径、报名人数上限和活动时间。
3. 查看报名名单与签到记录。
4. 对取消、满额、结束等状态进行管理。

### 第一版不做

- 基于深度学习的个性化推荐。
- 实时地图导航、复杂地图可视化。
- 人脸识别、支付、积分商城、即时通讯。
- 依赖未获授权的校园统一身份认证系统。

## 4. 系统架构

```
微信小程序
   │ HTTPS / JSON
   ▼
Spring Boot REST API
   ├── 用户与权限模块
   ├── 活动管理模块
   ├── 报名管理模块
   ├── 活动推荐模块
   └── 定位签到模块
   │
   ▼
MySQL
```

小程序负责页面展示、用户操作和位置授权；后端负责参数校验、活动状态判断、推荐排序、距离计算与数据持久化。关键规则必须在后端再次校验，不能只依赖小程序页面判断。

## 5. 主要业务流程

### 5.1 活动报名

1. 学生打开活动列表并查看详情。
2. 小程序请求后端检查活动是否已发布、是否在报名时间内、名额是否充足。
3. 后端检查该学生是否已经报名。
4. 报名成功后写入报名记录，并返回当前报名状态。
5. 活动满额或已截止时，后端返回明确提示。

数据库对“同一学生重复报名同一活动”设置唯一约束，避免并发请求造成重复数据。

### 5.2 活动推荐

第一版使用规则评分，确保实现简单且结果可解释：

- 兴趣类别匹配：匹配时加 3 分。
- 活动尚未开始且仍可报名：加 2 分。
- 活动地点距离用户较近（用户授权定位后）：加 1 分。
- 按总分从高到低排序；分数相同时，按活动开始时间排序。

不授权定位时，系统跳过距离加分，仍根据类别和活动时间推荐。用户没有设置兴趣时，按活动开始时间展示近期可报名活动。推荐结果只从已发布、未结束且仍可报名的活动中产生。

### 5.3 地理围栏签到

1. 学生在活动详情页点击“签到”并同意位置授权。
2. 小程序取得当前经纬度，向后端提交活动编号和坐标。
3. 后端检查活动状态、签到时间、报名状态及是否重复签到。
4. 后端计算用户位置到活动坐标的距离。
5. 距离小于或等于活动设定半径时，记录成功签到；否则返回“未进入签到范围”。

建议第一版使用 Haversine 公式计算球面距离。若坐标单位为弧度，距离可表示为：

```
a = sin²(Δlat / 2) + cos(lat1) × cos(lat2) × sin²(Δlon / 2)
distance = 2 × R × atan2(√a, √(1 - a))
```

其中 `R` 取地球平均半径约 6,371,000 米。代码实现时要检查经纬度是否为空、是否越界，并在数据库记录距离与签到结果，便于审核和测试。

## 6. 数据库初步设计

### user

- id：主键
- openid：微信用户标识；若未接入微信登录，开发阶段可使用测试账号标识
- nickname：昵称
- role：学生或管理员
- created_at：创建时间

### activity

- id：主键
- title：活动标题
- description：活动说明
- category：活动类别
- start_time、end_time：活动时间
- registration_deadline：报名截止时间
- capacity：人数上限
- venue_name：地点名称
- latitude、longitude：活动坐标
- checkin_radius_m：签到半径，单位米
- status：草稿、已发布、已下架或已结束
- organizer_id：发布者
- created_at、updated_at：创建和更新时间

### registration

- id：主键
- activity_id：活动编号
- user_id：学生编号
- status：已报名、已取消
- registered_at：报名时间
- 对 `activity_id + user_id` 建立唯一约束

### checkin

- id：主键
- activity_id：活动编号
- user_id：学生编号
- latitude、longitude：签到坐标
- distance_m：计算得到的距离
- result：成功或失败
- checked_at：签到时间
- 对 `activity_id + user_id` 建立唯一约束，避免重复成功签到

### user_interest（可选）

- id：主键
- user_id：学生编号
- category：兴趣类别
- 对 `user_id + category` 建立唯一约束

如果项目时间紧张，可把兴趣类别放入用户资料或在推荐页提供临时筛选，不一定单独建立偏好表。

## 7. API 初步设计

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/events` | 分页查询活动，可按类别、日期和状态筛选 |
| GET | `/api/events/{id}` | 查询活动详情 |
| POST | `/api/events` | 管理员创建活动 |
| PUT | `/api/events/{id}` | 管理员修改活动 |
| POST | `/api/events/{id}/registrations` | 学生报名 |
| DELETE | `/api/events/{id}/registrations/me` | 学生取消报名 |
| GET | `/api/events/recommendations` | 获取规则排序后的推荐活动 |
| POST | `/api/events/{id}/checkins` | 提交坐标并执行签到判断 |
| GET | `/api/users/me/records` | 查询当前用户报名与签到记录 |
| GET | `/api/events/{id}/records` | 管理员查看活动报名和签到记录 |

统一响应建议包含 `code`、`message` 和 `data`。分页接口统一接收 `page`、`size` 参数。服务端应校验活动编号、时间、坐标范围和用户权限。

## 8. 页面结构

- 首页：近期活动和推荐活动。
- 活动列表页：类别、日期筛选和分页加载。
- 活动详情页：活动信息、报名状态、地点和签到入口。
- 我的活动页：报名记录、签到结果。
- 兴趣设置页：选择关注类别。
- 管理页：活动列表、活动编辑、报名与签到记录。

## 9. 关键校验与测试场景

1. 未发布、已结束或已截止活动不能报名。
2. 同一用户重复报名不会产生重复记录。
3. 活动人数达到上限后不允许继续报名。
4. 未报名用户不能签到。
5. 活动签到时间之外不能签到。
6. 用户位于签到范围内时记录签到成功。
7. 用户位于范围外时拒绝签到并返回距离提示。
8. 用户拒绝定位授权时页面给出说明，其他活动浏览功能仍可使用。
9. 重复签到不会生成第二条成功记录。
10. 管理员和学生只能访问其角色允许的功能。

## 10. 开发顺序

1. 建立数据库表和 Spring Boot 项目，完成活动列表与详情接口。
2. 实现小程序活动列表、详情页和活动筛选。
3. 完成管理员发布活动功能。
4. 实现报名、取消报名与名额校验。
5. 实现兴趣设置与规则推荐。
6. 实现微信定位授权、后端距离计算和签到记录。
7. 逐项运行测试用例，保存真实结果和截图。
